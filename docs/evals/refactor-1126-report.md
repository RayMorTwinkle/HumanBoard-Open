# HumanBoard · 深链排版与版本审阅

2026-11-26。从备份源码复现深链排版的重复工作，并交付一个可独立运行的本地协作版本。两项工作的验证口径各自独立。

## 为什么选这条路径

在人已批注的画板上，Agent 可以提交结构化的图描述。思维图用父子关系表达结构，逻辑图用有向边表达关系。原项目的 `compileDiagram(input, previous)` 要把它们变成含矩形坐标、颜色、形状与连接锚点的 Scene。当一张合法图恰好是一条很深的链，查一次「孩子是谁」就要扫描完整节点表，计算跨度和摆放兄弟节点时又会反复访问后代。逻辑图也有对输入顺序敏感的路径。将一条路径的边从末端向起点排列，旧版每轮都要重新扫描前向边传播层级。

这些输入由脚本生成，均在原有 500 节点约束以内。它们复现了实现的实际性能特征。本次没有采集用户画板或线上的输入分布。

## 选择的数据结构

- 思维图先按原有顺序建立父节点到子列表的索引。验证祖先链时复用已确认的路径。每棵子树的跨度只求一次，父亲把颜色沿同一棵树传下去，保留原有顶层分支的配色和排序。
- 逻辑图按原边序建立出边表。深度优先遍历继续标记反馈边，让含回路的输入沿用原先的语义。其余边按逆完成顺序传播最长路径层级，汇入同一节点的多个前驱仍取最大层级。
- 摆放、手写批注所依赖的旧坐标、避让、锚点以及输出结构沿用原契约。上一版位置、节点碰撞与文字测量仍然需要处理，不能据局部遍历的改进给整个编译函数标注线性复杂度。

## 怎样判断一次运行有效

计时样例逐轮对完整 Scene 计算摘要，四个样例两臂全部相同。另有 60 个固定种子生成的结构、1 个带旧坐标的编辑场景、6 个非法输入。脚本逐一深比较输出，或者断言同样的错误消息。样例覆盖并列排序、父节点晚于子节点出现、自定义颜色、共享后继、回边、重复标识、未知端点以及不支持的布局。

完整序列化结果相同提供了比「节点数相同」更强的兼容性证据。两版若共享同一缺陷，等价检查仍可能通过，因此项目原有的布局断言与新增的手工用例也独立运行。原仓两臂均通过类型检查、完整 Bun 测试和 Web 构建。备份 374 项通过，候选 376 项通过。Vite 两端均提示部分压缩后的 chunk 超过 500 kB。

## 面试中可以追问的三个决策

**产品经理 · 哪个体验值得保护？** 图上某张卡片旁边已有手写标注时，Agent 只补一句说明，使用者希望旧批注仍贴着原对象。因此既测「首次从结构生成布局」，也测「拿着旧坐标再编译」。单独把极端图的耗时讲成全体使用者的等待时间，会掩盖小图几乎测不出差别的事实。下一步要验证的是固定设备上的输入到绘制延迟，以及真实图的深度分布。

**Agent 开发 · 人与 Agent 同时改一处时，谁能提交？** 公开卡片版把审阅问题拆成版本前置条件与三方合并。提交指明读到的 base，写入前在事务里对照当前 head。审阅固定源和目标的两个 head。改动命中不同字段可以同时保留，同字段写入两个不同值时，预览给出祖先、目标、来源三份值。选择以具体字段与版本为单位，旧预览遇到新的头就失效。MCP 与浏览器共用存储，因此这个契约在两种入口都成立。

**后训练与评测 · 什么可以当作判分信号？** 在布局任务上，可对完整 Scene、旧坐标和拒绝原因给出确定性判分。对提案工具，可以把「读取既定版本」「隔离写入分支」「审阅后再合并」拆为可观察动作，并加一道同时改标题的反例。后者是可在本地演练的轨迹设计。本次实验测的是编译器，未采样模型输出，也没有模型成功率或偏好胜率。

## 结论能覆盖到哪里

两轮深链测量都支持减少重复遍历的改造方向。本次同时改了邻接索引、跨度缓存、颜色继承和校验，没有分别消融这几项改动。逆序边和带旧坐标的编辑也有实测改善。小图的绝对差别不足百分之一毫秒，应保留原始抖动一起阅读。没有浏览器帧率、网络同步、并发吞吐、用户工作量或生产百分位的前后实验，表中的数字仅用于指定输入的一次编译。

公开版使用 Node 原生 SQLite 的卡片模型，本报告的渲染前排版数据来自原 TypeScript 编译器。运行公开画板可以复核版本行为，运行对照脚本可以复核排版数据。

## 本地复现

从公开仓根目录运行。首次安装只在评测子目录取用锁定的 Zod，复跑需要 Bun、Node.js、npm 与 POSIX shell。画板应用自身无需此依赖。

```sh
cd docs/evals/replay
npm ci --ignore-scripts --no-audit --no-fund
./run.sh > replay.json
```
